## Data contract for team collaboration

- A single row represents **one calendar month**. The column named `date` contains the **first day of the month**, formatted `YYYY-MM-DD`.
- One feature per column, using the exact names above, numeric values, and missing observations left as blank/NaN (never silently zero-fill).
- Your output is `data/processed/z1_z3_monthly.csv`. Your teammate should deliver `data/processed/z4_z6_monthly.csv` with the same `date` convention.
- The download notebook saves source observations individually under `data/raw/fred/` and raw **monthly levels** under `data/interim/z1_z3_levels_monthly.csv`.
- The team can merge on `date` after both exports are available. Avoid merging by row number.
- **No lag or standardization in the downloaded feature files**. Apply time alignment, one-month lags, and training-only standardization in the later model-building stage.

Example for the eventual merge (run only after both exports exist):

```python
import pandas as pd
z1_z3 = pd.read_csv('data/processed/z1_z3_monthly.csv', parse_dates=['date'])
z4_z6 = pd.read_csv('data/processed/z4_z6_monthly.csv', parse_dates=['date'])
all_z = z1_z3.merge(z4_z6, on='date', how='outer', validate='one_to_one')
all_z = all_z.sort_values('date')
```

## Sample dates and statistical interpretation

- Requested observation window is **January 2010–October 2026**, using data from December 2009 to calculate the first labor change. October 2026 is the last complete calendar month as of 25 November 2026. Some series may not yet be updated through the end date; this will appear as missing observations.
- EDA displays the full downloaded sample but reports **ADF and KPSS stationarity tests for the training period (2010–2020)** to avoid selecting transformations based on the 2021+ test period.
- **ADF** null: unit root. **KPSS** null: level stationarity. Mixed answers are common; use time plots and economic reasoning too.
- FRED currently available observations are not automatically a **real-time data vintage**. A serious walk-forward forecast must account for publication lags, revisions, and data actually available at each historical forecast origin (consider ALFRED later).
- Tests of level stationarity with `regression='c'` are diagnostic, not proof. Structural breaks, persistent but stationary processes, and seasonality can complicate their interpretation.
